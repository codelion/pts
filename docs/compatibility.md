# Compatibility with older datasets

PTS reads the pivotal-token and thought-anchor JSONL files that earlier releases
produced. You do not have to convert anything — every command upgrades them on
load.

```bash
# An older pivotal-token file, read directly.
pts export --input-path pivotal_tokens.jsonl --format dpo --output-path dpo.jsonl \
           --model Qwen/Qwen3-0.6B --dataset codelion/optillmbench --find-rejected-tokens
```

To convert a file explicitly:

```bash
pts migrate --input-path pivotal_tokens.jsonl  --output-path events.jsonl
pts migrate --input-path thought_anchors.jsonl --output-path events.jsonl
```

And to render events back into the older shapes for consumers that still expect
them:

```bash
pts export --format pivotal_tokens  --input-path events.jsonl --output-path tokens.jsonl
pts export --format thought_anchors --input-path events.jsonl --output-path anchors.jsonl
```

The round trip is exact for every field the older formats defined; it is covered
by tests.

## How older fields map onto the event schema

### Pivotal tokens

| older field | event field |
|---|---|
| `pivot_token` | `label` |
| `pivot_context` | `context` |
| `pivot_token_id` | `token_id` |
| `prob_before` / `prob_after` / `prob_delta` | unchanged |
| `is_positive` | unchanged (now a field, not a method) |
| — | `event_type: "pivotal_token"`, `granularity: "token"`, `score: abs(prob_delta)` |

### Thought anchors

| older field | event field |
|---|---|
| `sentence` | `label` |
| `sentence_id` | `position` |
| `prefix_context` | `context` |
| `prob_with_sentence` | `prob_after` |
| `prob_without_sentence` | `prob_before` |
| `importance_score` | `score` |
| `sentence_category` | `category` (remapped, below) |
| everything else (`suffix_context`, `alternatives_tested`, `causal_dependencies`, …) | `metadata.*` |

### Categories

The older eight-category sentence vocabulary maps onto the one taxonomy shared by
all three scales, which is what makes cross-scale chains detectable at all:

| older category | unified category |
|---|---|
| `problem_setup` | `interpretation` |
| `plan_generation` | `planning` |
| `fact_retrieval` | `fact_retrieval` |
| `active_computation` | `computation` |
| `uncertainty_management` | `uncertainty` |
| `result_consolidation` | `consolidation` |
| `self_checking` | `verification` |
| `final_answer_emission` | `final_answer` |

## Python API

Older imports still resolve:

```python
from pts.core import PivotalToken, PivotalTokenSearcher      # works
from pts.thought_anchors import ThoughtAnchorSearcher        # works
from pts.storage import TokenStorage                         # works
```

But the objects are now unified events:

```python
tok = PivotalToken(query="...", pivot_context="...", pivot_token=" Wait", ...)
tok.label          # " Wait"     (was tok.pivot_token)
tok.context        # "..."       (was tok.pivot_context)
tok.is_positive    # True        (was tok.is_positive(), a method)

from pts.events import to_legacy_pivotal_token
to_legacy_pivotal_token(tok)   # the older dict shape, if you need it
```

`import pts` does not pull in torch or transformers. The event schema, storage,
classification, and linking layers are pure Python; anything that touches a model
loads lazily on first access.

## Known issues in datasets generated by earlier releases

Several defects in earlier code produced wrong numbers. If you have datasets or
published results generated before these fixes, they may be affected. The current
code does not have these problems.

**Thought-anchor probability deltas could be invalid.** Under memory pressure the
old sentence search blanked already-processed sentences in place while later
iterations still read that list to build prefixes, so every `prob_delta` computed
after that point was measured against a blank-padded prefix. Those numbers were
wrong, not merely noisy.

**Whole examples could be silently dropped.** The same cleanup deleted its own
`reasoning_trace` parameter, guaranteeing an `UnboundLocalError` on the next
anchor; a broad `except` swallowed it and the example vanished with no
indication.

**DPO exports contained no positive tokens.** `--find-rejected-tokens` ran its
rejected-token search against a dummy oracle that reports every completion as a
success, so every candidate scored `P(success) = 1.0`, the acceptance test could
never fire, and every positive token was dropped. Those DPO datasets contain only
negative-delta tokens, whose partner was chosen by next-token likelihood rather
than by any measured effect. `--find-rejected-tokens` now requires a real oracle
(`--dataset <source>`) and refuses rather than fabricating pairs; every pair
carries `metadata.counterpart_verified`.

**Datasets built through the CLI were doubled.** The searcher wrote each token to
storage and the CLI wrote it again. Storage is now idempotent by `event_id`.

**Cached probabilities leaked across categories.** The cache key omitted
`category`, which selects a different prompt, so two categories with the same
query returned each other's cached probability.

**Steering vectors read the wrong position under left-padding.** The extractor
assumed right-padding; it now checks `tokenizer.padding_side`.

## Not included

- **Latent interventions** (steering or ablating a meta-token and re-measuring
  success). Latent events are observational only. See
  [`latent_pts.md`](latent_pts.md).
